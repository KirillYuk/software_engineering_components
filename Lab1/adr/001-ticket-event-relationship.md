# ADR 001: Зв'язок Ticket з Event через Booking

## Контекст
Сутність **Ticket** повинна бути пов'язана з конкретною подією, місцем та бронюванням. Треба визначити чи зберігати `eventId` безпосередньо в **Ticket**.
## Рішення
Не додавати `eventId` до **Ticket**

Подію для квитка можна визначити через зв'язок:
**Ticket -> Booking -> Event**

**Ticket** містить `bookingId`, `seatId`, `unitPrice`

## Альтернативи

### Додати `eventId` до Ticket

- Перевага - подію можна було б отримати з **Ticket**
- Недолік - `eventId` дублював би інформацію, яка вже визначається через **Booking**, і створював би зайву залежність

### Визначати **Event** через **Booking**

Цей варіант не дублює `eventId` у **Ticket** і зберігає модель простішою

## Наслідки

Модель не містить дубльованого `eventId` у **Ticket**. Подія визначається через **Booking**, а `Ticket.unitPrice` зберігає фактичну ціну конкретного квитка незалежно від `Event.basePrice`
